# Simulink 文档驱动建模助手 PRD

**版本：** v1.0
**目标平台：** MATLAB/Simulink R2025b
**应用场景：** 电机控制、温度控制、液位控制、机械系统等
**产品定位：** 建模辅助工具，不替代用户进行最终仿真。

## 1. 产品背景

工科学生在使用 Simulink 建模时，需要反复完成以下工作：

- 阅读建模需求文档；
- 理解系统结构和控制逻辑；
- 选择对应的 Simulink 模块；
- 确定模块连接关系；
- 整理模块参数、单位和初始条件；
- 绘制模型结构图；
- 设置仿真时间、采样时间和输出信号。

本系统负责自动完成上述前期建模准备工作，用户根据系统输出在 MATLAB/Simulink R2025b 中手动搭建并运行模型。

## 2. 产品目标

系统应实现：

1. 解析 DOCX、PDF 和 Markdown 文档；
2. 提取系统目标、输入输出、模块、方程、参数和仿真条件；
3. 识别电机控制、温控、液位控制和机械系统等建模场景；
4. 生成可供用户复现的 Simulink 模型结构图；
5. 输出模块参数表、连接关系表和仿真配置建议；
6. 标注缺失参数、推断内容和待确认问题；
7. 保留原文位置和参数来源，便于检查；
8. 判断仿真结果是否符合工程要求；
9. 帮助用户减少建模准备工作，但保留用户最终判断权。
10. 模型需要脚本文件时，输出.m代码

## 3. 非目标

首版系统不负责：

- 生成或保存 `.slx` 文件；
- 自动打开 MATLAB；
- 自动运行仿真；
- 自动调参或自动整定控制器；
- 自动生成 Stateflow 模型；
- 自动生成 Simscape 物理网络；
- 使用 Control System Toolbox 完成控制系统分析；
- 在关键参数缺失时静默猜测。



## 4. 用户角色

主要用户为：

- 自动化、电气、机械、控制相关专业学习者；
- 需要反复进行控制系统建模的研究人员；
- 需要快速整理 Simulink 建模方案的工程人员。

用户始终负责：

- 检查需求解析结果；
- 确认模块结构；
- 确认参数和假设；
- 在本地 Simulink 中搭建模型；
- 运行仿真并分析结果。

## 5. 核心使用流程

```
上传 DOCX / PDF / Markdown
        ↓
解析文档内容
        ↓
提取系统结构、参数和公式
        ↓
识别缺失项与歧义
        ↓
用户确认解析结果
        ↓
生成 Simulink 模型方案
        ↓
生成模型结构图和参数表
        ↓
用户在 Simulink 中手动搭建与仿真
```

系统应将模型状态标记为：

- `可直接搭建`
- `补充参数后可搭建`
- `结构存在歧义`
- `仅供参考`

## 6. 输入需求

### 6.1 支持格式

- `.docx`
- `.pdf`
- `.md`
- `.markdown`

PDF 支持：

- 文本型 PDF：直接解析；
- 扫描型 PDF：通过 OCR 解析，并标注较低置信度；
- 公式、表格和图片内容需要单独标注解析状态。

### 6.2 需求内容

输入文档可以包含：

- 系统功能描述；
- 控制目标；
- 输入信号和输出信号；
- 系统结构；
- 数学方程；
- 电机或机械参数；
- 控制器参数；
- 负载和扰动；
- 初始条件；
- 采样时间；
- 仿真时间；
- 求解器要求；
- 需要观察的输出量；
- 性能指标；
- 约束条件。

## 7. 功能需求

### FR-01 文档解析

系统应提取：

- 标题和章节；
- 正文段落；
- 表格；
- 数学公式；
- 图片说明；
- 参数名称和数值；
- 单位；
- 输入输出信号；
- 仿真配置。

每个提取结果应记录来源位置，例如：

- 第 2 页；
- 第 3 节；
- 第 4 个表格；
- 第 5 段。

### FR-02 需求结构化

系统应将文档转换为统一模型描述，至少包括：

- 系统名称；
- 系统类型；
- 控制目标；
- 输入信号；
- 输出信号；
- 子系统；
- 模块；
- 信号；
- 数学方程；
- 参数；
- 初始条件；
- 仿真配置；
- 假设；
- 待确认项。

### FR-03 模型结构生成

系统应根据解析结果生成 Simulink 风格的模型结构图，包括：

- 模块名称；
- 模块编号；
- 输入端口；
- 输出端口；
- 信号方向；
- 连线关系；
- 信号名称；
- 子系统边界；
- 反馈回路；
- 关键参数标注。

模型图应优先采用从左到右的信号流布局。

### FR-04 电机控制支持

电机控制是首版重点场景。系统应支持识别和绘制常见结构：

```
给定值
  ↓
误差计算
  ↓
控制器
  ↓
执行环节
  ↓
电机模型
  ↓
输出量
  ↓
反馈环节
  └────────返回误差计算
```

根据输入文档，模型可能包含：

- 速度给定；
- 位置给定；
- 电流给定；
- 误差计算；
- 比例、积分和微分环节；
- 电压或电流限制；
- 电机电气方程；
- 电机机械方程；
- 负载转矩；
- 摩擦；
- 扰动；
- 速度、位置和电流输出；
- Scope 或 To Workspace。

系统不得固定套用某一种电机模型，应根据文档中的电机类型和方程生成建议。

### FR-05 其他领域支持

系统应支持以下领域的通用信号流建模：

- 温度控制；
- 液位控制；
- 机械系统；
- 其他可由基础动态方程描述的控制对象。

对于无法确定的物理关系，系统应输出待确认项，而不是自动补全。

### FR-06 模块清单

系统应输出模块清单：

| 编号 | 模块名称 | 推荐模块类型 | 输入 | 输出 | 说明 |
| ---- | -------- | ------------ | ---- | ---- | ---- |
|      |          |              |      |      |      |

模块类型应使用用户可以在 Simulink 中查找的标准名称，例如：

- Gain；
- Sum；
- Product；
- Integrator；
- Derivative；
- Transfer Fcn；
- State-Space；
- Saturation；
- Switch；
- Unit Delay；
- Step；
- Constant；
- Scope；
- Subsystem。

系统只负责推荐模块和参数，不负责在 MATLAB 中创建这些模块。

### FR-07 参数表

系统应输出：

| 模块编号 | 参数名称 | 参数值 | 单位  | 来源     | 状态   |
| -------- | -------- | ------ | ----- | -------- | ------ |
| B01      | 电枢电阻 | 2.4    | Ω     | 用户文档 | 已确认 |
| B02      | 转动惯量 | 未提供 | kg·m² | 缺失     | 待补充 |

参数状态包括：

- 已确认；
- 文档推断；
- 默认假设；
- 待用户确认；
- 缺少数值；
- 单位不明确；
- 存在多个候选值。

### FR-08 连线表

系统应输出：

| 起点模块/端口 | 终点模块/端口 | 信号名称 | 信号含义 |
| ------------- | ------------- | -------- | -------- |
|               |               |          |          |

连线表用于辅助用户在 Simulink 中逐条连接模块。

### FR-09 仿真配置建议

系统应根据文档输出建议：

- 仿真起始时间；
- 仿真结束时间；
- 连续或离散系统；
- 推荐求解器类型；
- 固定步长或最大步长；
- 采样时间；
- 初始状态；
- 输入信号参数；
- 观测信号；
- 输出记录方式。

这些内容属于建议，用户仍需在 MATLAB/Simulink 中最终确认。

### FR-10 假设与待确认项

系统必须单独列出：

- 缺少的关键参数；
- 未确定的模块类型；
- 未确定的信号方向；
- 未确定的单位；
- 不明确的初始条件；
- 公式中的符号歧义；
- 文档内部矛盾；
- 系统自动推断的内容。

任何关键假设都不得只隐藏在模型图中。

### FR-11 可追溯性

每个模块、参数、信号和假设应能够追溯到：

- 原文页码；
- 章节；
- 段落；
- 表格；
- 公式；
- 图片编号。

如果内容来自系统推断，应标记为“系统推断”，不得伪装成用户输入。

## 8. 输出内容

每次生成一个完整的建模方案包：

```
建模方案/
├─ 需求解析结果.md
├─ Simulink模型结构图.svg
├─ Simulink模型结构图.png
├─ 模块清单.csv
├─ 模块参数表.csv
├─ 连线关系表.csv
├─ 仿真配置建议.md
├─ 假设与待确认项.md
└─ 文档来源追踪表.csv
```

默认输出不包含 `.slx` 文件。

## 9. 页面和交互

系统建议包含以下页面：

1. **项目首页**
   创建项目、上传文档、查看历史版本。
2. **文档解析页**
   查看原文、提取内容和解析置信度。
3. **需求确认页**
   修改系统类型、参数、输入输出和歧义项。
4. **模型图页面**
   查看、放大、缩小和导出模型结构图。
5. **参数页面**
   查看和编辑模块参数、单位、来源及状态。
6. **校验页面**
   查看缺失项、单位问题、连接问题和结构冲突。
7. **导出页面**
   导出图像、表格、Markdown/PDF 报告，以及用户主动要求的 `.m` 文件。

## 10. 非功能需求

- 同一份文档和同一版本配置应生成一致的模型方案；
- 解析结果、参数和模型图之间不得出现冲突；
- 所有参数必须带单位或明确标记“单位未知”；
- 所有推断内容必须带置信度；
- 关键缺失项必须在最终报告中显示；
- 模型图应清晰可读，模块和连线不能重叠；
- 支持对模型方案进行版本保存和对比；
- 生成结果应适配 MATLAB/Simulink R2025b 的人工搭建流程；
- 系统不得声称模型已经完成仿真验证。

## 11. MVP 范围

首版必须完成：

- DOCX、PDF、Markdown 输入；
- 文本和表格解析；
- 电机控制需求解析；
- 基础控制系统结构识别；
- 模型结构图生成；
- 模块清单生成；
- 参数表生成；
- 连线表生成；
- 仿真配置建议；
- 假设和待确认项输出；
- 参数和模块的原文追踪；
- PNG/SVG/Markdown/CSV 导出。

首版暂不要求：

- 自动生成 `.slx`；
- 自动运行 MATLAB；
- 自动运行仿真；
- 自动调参；
- Stateflow；
- Simscape；
- Control System Toolbox；
- 复杂多物理场建模；
- 自定义 S-Function；
- 自动识别所有扫描公式。

## 12. 验收标准

给定一份包含直流电机速度闭环控制需求的文档，系统应能够：

1. 正确识别给定值、误差、控制器、电机对象和反馈信号；
2. 生成结构完整的 Simulink 模型图；
3. 列出每个模块的推荐类型；
4. 输出模块参数、单位和来源；
5. 输出完整连线关系；
6. 标注缺失的电机参数和初始条件；
7. 给出仿真时间、采样时间和观测信号建议；
8. 允许用户修改解析结果；
9. 导出的图和表格内容保持一致；
10. 用户能够按照输出结果在 MATLAB/Simulink R2025b 中手动复现模型。

## 13. 核心产品原则

系统的最终定位是：

> **把建模需求转化为清晰、可检查、可复现的 Simulink 建模方案，帮助用户减少查找、整理和绘图工作；模型确认、手动搭建和仿真分析仍由用户完成。**
